# ADR-0001：TC264共享C核心与保守资源基线

- 状态：Accepted（用户已认可硬件及技术路线；实现尚未完成）
- 日期：2026-11-14
- 适用范围：疯狂电路视觉组软件，硬件v0.3

## 背景

本车使用TC264_BTB、MT9V034、130差速双电机、IMU660RB和IPS114。用户确认SRAM总规格为240KB，要求保守计算资源，PC先验证算法并尽量共享C源码。Soberup参考项目包含完整控制链，但其GPIO、IMU660RC、原比赛路线、双核协作和控制参数不能视作本车可直接部署。

## 决策

1. `soberup/upstream/`保留固定提交`7abfdac0d0156576ba5186716a7c1e42992359ca`，以707文件清单校验，不在原快照改造。
2. 新建本车应用和板级适配；以核验过的逐飞TC264官方库作为候选驱动基础，版本独立记录，不把V3.4.6覆盖到原V3.4.1快照。
3. 核心算法采用C99/C11兼容子集，同一份源码供PC与MCU调用；核心不直接依赖逐飞总头、设备寄存器、显示或文件系统。
4. 初版单CPU应用，先证明实时性与采集所有权，再评估双核。目标视觉30Hz、控制200Hz，实际周期及PID通过测量确认。
5. 240KB SRAM按算法≤96KB、系统预留96KB、保护余量48KB设计；1KB=1024B，并逐链接区核验。默认不使用屏幕完整帧缓存和3072点轨迹记录。
6. 首先实现闭合路线调试里程碑，返回发车区并由裁判口径确认N≥2；正式验收依比赛阶段采用对应门槛，国赛75%覆盖属于有效性要求。超过必要门槛的覆盖收益优化在可靠完赛之后。

规则追补（同日）：用户指定参照第21届疯狂电路组，见[全国规则基线](../research/2026-11-14-national21-rule-baseline.md)。全国允许指定ST IMU，但成品主板/驱动板的自制资格另行检查；文杰杯三科赛制仍保留。本ADR的硬件和共享C资源决策不变。

## 考虑过的方案

| 方案 | 收益 | 不采用为主路线的原因 |
| --- | --- | --- |
| 原工程直接烧录 | 前期工作少 | 硬件和比赛路线不匹配，固定停车及启动组织未经本车验证 |
| 全部从零编写 | 接口完全自主 | 重复开发已存在的图像和控制思路，增加调试成本 |
| 在原快照混改SDK和算法 | 暂时文件少 | 来源不清、难以差异回归、无法继续证明上游完整性 |
| 双核一开始并行迁移 | 潜在吞吐更高 | 在帧交接、内存与时序未验证前扩大问题面 |

## 后果与复审条件

需要为原全局变量增加显式接口，建立本车采样单位和参数版本；前期会比复制文件多一些适配工作，但PC结果、板上行为和来源更容易核对。当前接受的是设计，不是接受当前固件已达标。

若视觉最坏耗时不满足预算、单CPU采集存在不可消除冲突、规则禁止预存路线，或算法数据超过96KB，应补充新ADR说明调整依据；不暗中扩大内存或改用双核。细节见[架构文档](../architecture/system-architecture.md)。
