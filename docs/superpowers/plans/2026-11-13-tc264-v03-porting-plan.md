日期：2026-11-13。目标：在逐飞官方TC264工程上接入可由PC和MCU共用的C99/C11兼容算法核心。本文补充并优先约束[原赛题实现计划](2026-11-13-wenjie-vision-algorithms.md)，不重做已确定的赛题任务。

依据：[硬件型号与保守资源](../../hardware-components.md)、[硬件开发核验](../../hardware-profile.md)、[第二轮仓库筛选](../../research/2026-11-13-tc264-v03-repository-selection.md)。方案已获认可，[Soberup main源码基线](../../../soberup/README.md)已经下载并验证，未修改上游。以下应用适配路径和测试仍是后续实施内容。

## 1. 代码组织

- 已存在`soberup/upstream/`：提交7abfdac0d015的原样main源码和随附V3.4.1库，保留完整工程、依赖、许可和哈希，不直接修改。
- 计划建立`firmware/vendor/TC264_Library/`：锁定官方V3.4.6已核验提交；保留完整启动、iLLD、ADS工程和许可。不在Soberup原始快照中混换库，不把两份库同时加入链接。
- `firmware/app/platform/tc264/board_config.h`：唯一板级映射，集中相机、PWM/DIR、GPT12、SPI、UART与中断配置。引脚未核实时不写可运行的猜测值。
- `firmware/app/platform/tc264/board_port.[ch]`：相机所有权、时间、编码器、IMU660RB、执行器；屏蔽逐飞类型和寄存器。
- `firmware/app/vision/`、`navigation/`、`control/`：纯C核心，不含`zf_common_headfile.h`、IPS调用或Tasking段声明。
- `tools/host/`：同一份C核心的PC构建；Python负责图像读取/标注/指标，不能只测试Python替身。
- `config/calibration/`：每台车自己的相机、编码器、IMU、轮距和PWM参数；不复制原队默认标定。

实施时选择一种放置方式接入ADS工程，不同时复制两份算法源码：可由ADS引用项目统一的核心目录，或由固定导入过程生成工程引用，避免PC和固件各改一份。

## 2. 四个先行任务

### H0：锁定工程与硬件连接

- [ ] 导入官方基础ADS工程，确认TC264D目标及实际编译器。记录commit、版本、构建参数和原始.map。
- [ ] 与本车V1.1原理图逐项填写`board_config`映射表，列出定时器/DMA/SPI/中断冲突。
- [ ] 将用户P11.9—P11.12候选范围逐脚验证为左/右PWM、DIR；独立确认使能/睡眠引脚及停车状态。
- [ ] 验证调试器支持AURIX与DAS；未拿到主板确切原理图时可以做PC核心，不能声称板级接线已确认。

验收：能编译空应用，映射表每项有原理图页或实测依据；不使用Soberup的P33组作为本车默认输出。

### H1：驱动独立验收

- [ ] 相机使用官方MT9V03X接口，以188×120采集；记录初始化返回值、配置口路径、seq和采集时间。
- [ ] 编码器先按实物确认A＋DIR或AB模式，再调`encoder_dir_init`或`encoder_quad_init`；若AB，遵守官方接口TIM2/3/4限制。
- [ ] 测手动正反转一圈、整轮若干圈、换向和高速，计算有效count/rev及最大周期count。读取int16不得溢出；累计里程用更宽整数。
- [ ] 计数优先采用连续计数器模差方案并验证硬件模式；若采用读后清零，量化读清竞态和失脉冲，不把临界区屏蔽CPU中断当成暂停外部计数。
- [ ] RB用`imu660rb_*`接口，先自检再换算成明确物理单位；零偏与安装矩阵每车记录，不保留RC设备依赖。
- [ ] PWM低占空比测试左右正负、停机和命令超时；130电机参数从低速重整定。
- [ ] IPS只显示状态与小图，测同步SPI最长阻塞，不能进入速度控制中断绘屏。

验收：每项可独立重复；拔相机/IMU错误和命令过期都可进入受控停止。规则不允许某辅助传感器时，配置禁用相关策略，并记录降级效果。

### H2：帧所有权、内存和PC一致性

- [ ] 先不修改官方采集，测帧完成到下次VSYNC的可用窗口；完成标志不是锁。
- [ ] 实现“完整采集→确认DMA停止且阻止本次下一帧重启→复制到只读快照→按后续完整VSYNC恢复”的握手，或实现经过验证的乒乓采集；不能只在主循环`memcpy`后假设完整。
- [ ] 同一seq在获取和释放前后不被写；允许主动跳帧，但不允许撕裂、无界排队或从半帧位置恢复采集。
- [ ] 每张图22,560B，单独列明放入DSPR0还是DSPR1；使用map确认CSA、栈和SDK余量，不用普通堆分配大图。
- [ ] 为同一组原始帧在PC与TC264比较二值图、点集、状态转移和左右轮目标；规定浮点容差和无效输出语义。
- [ ] 全黑、全白、平行白线、断电噪点、器件伪路口、倒车负轮速和计数器跨零各有回归用例。

验收：SRAM总规格240KB，算法数据≤96KB、系统预留96KB、保护余量48KB；三张图合计67,680B计入算法预算，其余状态也不能超桶。各链接区域无溢出，栈水位达标；PC与板端同源算法输出在既定容差内一致。

### H3：有顺序地吸收Soberup

- [ ] 先实现简单OTSU/扫描线基线，再用失败样本决定是否迁移Soberup局部补偿与爬线；控制引入的状态和数组规模。
- [ ] 把有界补线的输入改成图像/ROI/本车尺度配置，不依赖原队全局路线变量；用邻近平行支路负例验证。
- [ ] 把路口状态逻辑接入本项目事件和超时接口，独立处理三端器件；重新设防抖和重入冷却。
- [ ] `get_yaw`适配到RB计算结果，角度、角速度、积分周期全部明确；丢IMU新数据时不重复当新样本积分。
- [ ] 不迁移原队N30轮速增益、编码器尖峰300阈值、16cm标定、GPIO和既有赛道表。
- [ ] 地图许可确认后再导入本校动作序列；唯一器件计数、30秒遗漏罚时、合法回程和未知节点策略按原赛题计划开发。

验收：按原计划Task3—9逐项回放和实车测试，保留低速保底固件。未完成全局规划时不将“固定路线执行成功”写成“在线建图成功”。

## 3. 调度、单位与边界

首版由CPU0执行应用和算法，CPU1仅保留SDK必要启动/空闲；若相机SDK已有必要服务中断归属，先核实再调整。建议初始速度环200Hz，IMU按实际新数据更新，视觉目标30Hz，显示目标5Hz及小区域刷新；均为待测工程目标。官方相机50FPS配置与算法30Hz可以通过主动跳帧解耦。

方向层输出`v_mps`与`omega_radps`，按有效轮距B得`vL=v-omega*B/2`、`vR=v+omega*B/2`；轮速层用已校准的counts→m/s反馈。IMU驱动gyro的°/s在适配层转换；禁止把counts/5ms、rpm、m/s混用同一PID。

实测端到端延迟、视觉P95和最大控制抖动。未满足截止期先降低显示负载、缩ROI/分辨率和车速，之后才评估CPU1视觉。分核时用不可变观测快照、序号/双缓冲及AURIX相应同步和地址规则，不仅靠volatile。

性能任务包含编码器边沿吞吐与最大count、IMU采样新鲜度、DMA连续采集、Flash常量访问、SPI显示阻塞；不能用PC耗时推断200MHz目标板性能。
