# 疯狂电路视觉智能车：硬件与软件开发基线

版本：用户硬件规格v0.3的项目落档与核验补充。更新日期：2026-11-13。用途：C算法、PC回放、TC264移植与实车验收。**器件型号和算法资源统一以[硬件型号与保守资源文档](hardware-components.md)为入口：SRAM总规格240KB，算法数据预算≤96KB。** 本文保留官方库接口和链接配置的核对细节。

事实分为三层：**用户给定配置**表示本车选型；**官方库默认值**表示本轮源码的设置；**实测值**只有上板测量后才能填写。库默认引脚不自动等于学习板接线。

## 3. 240KB总SRAM与保守工程预算

**本车SRAM总规格为240KB，按用户确认值记录。** 项目采取保守预算：算法数据≤96KB、SDK/CSA/栈/中断等预留96KB、未分配保护余量48KB，均以1KB=1024B核算。这是设计预算，不是已经实测的可用空间。

布局核对备注：本轮读取的官方链接模板`Lcf_Tasking_Tricore_Tc.lsl:46-50,115-147`将DSPR0/1和PSPR0/1分区声明。模板中的局部数据区域数值不用于替换240KB器件总容量；落地时仍须检查大数组、DMA和CSA/栈是否各自放得下，以最终工程.map为准。保护余量也不等于可互换的连续数据堆。

| 数据 | 字节数 | 说明 |
| --- | ---: | --- |
| 原厂采集帧188×120 | 22,560 | 驱动已存在，不重复增加同名数组 |
| 算法只读快照/第二灰度帧 | 22,560 | 完整帧交接正确后才保留；不能一边DMA写一边复制而不检测完整性 |
| 8位二值图188×120 | 22,560 | 首版方便回放一致性；RAM不足再评估按行或位图 |
| 上述三张图合计 | 67,680 | 占240KB总规格约27.5%；计入96KB算法桶，不占用系统预留来堆额外图像 |
| RGB565一行，按240像素计 | 480 | 屏幕方向/驱动最大宽度决定实际栈用量，不是全屏帧 |
| 80×60灰度图 | 4,800 | 仅在吞吐不达标时评估分辨率降级 |
| 752×480灰度图 | 360,960 | 352.5KiB，超过本片内预算，不采用 |

67,680B不能全放进72KiB的DSPR0再期待控制、CSA和中断栈仍有充分空间。静态缓冲应按链接脚本明确分配并检查.map；首版单核运行也可以评估把大数组放到另一DSPR的全局可访问地址，但必须验证地址别名、DMA可达性及链接配置，不能仅靠普通malloc。

完整预算还需统计左右边界/中心点、直方图、路线表、SDK变量、CSA、用户栈、中断栈及对齐间隙。每个实际使用的数据区域分别保留余量，并用栈水位和运行测试核对；“总剩余20%”不代表某个局部区不会溢出。

不放全尺寸浮点逆透视x/y查表：两张188×120 float表需180,480B；优先离线生成必要行/点映射或小表，常量放Flash，算法核心使用float而非默认双精度大数组。
