# 2026文杰杯疯狂电路组：当前完赛能力评估

评估日期：2026-11-14。对象：当前工作区资料与Soberup锁定源码，硬件v0.3。方法：规则对照、调用链静态检查、资源预算和仓库证据核查；没有运行外部车载代码，没有ADS编译或实车测试。

补充依据：用户随后明确“具体规则参照21届全国赛疯狂电路组”，本评估已纳入[全国赛规则、后期流程和问答核对](../research/2026-11-14-national21-rule-baseline.md)。下列N≥2、三科、278秒保留为文杰杯PPT口径；全国赛后期单科安排、国赛75%覆盖和自制电路要求另行区分，不能当作同一规则版本。

## 1. 结论

**当前不能认定达到完赛要求；现有原始参考工程也不具备本车直接部署条件。** 硬件选型和参考算法具备继续实现的基础，但本车外设适配、比赛任务闭环、帧交接、非阻塞停车、资源与实车验证仍未闭合。这个结论是“缺少实现和证据”，不是认定TC264算力不足，也不代表实体车一定尚未组装。

当前处于“参考基线与设计阶段”，尚无证据达到“本车可编译”“稳定循线”或“三科有效完赛”。不能用开源项目的演示、README或源码完整性校验代替本车验收，不给出无依据的完成百分比。

## 4. 静态源码发现与影响

优先级：P0为本车部署或比赛任务闭环的直接阻碍；P1为可靠性/资源关键风险；P2为完赛后优化。行号是本次固定快照中的导航位置，具体以函数和当前代码为准。

### F01 · P0：硬件适配尚未完成

`initialize.c:27`和`MahonyAHRS.c`调用IMU660RC接口，本车为IMU660RB；`motor.h:33`附近为P33组电机引脚，本车资料为P11.9—P11.12候选组。不能以简单改名字替代器件初始化、单位转换和坐标轴校准，也不能未经接线核对判定某组引脚正确。编码器原使用A+DIR，需和本车接线/模式一致。

**处理：**先建立实物原理图到GPIO/外设通道表；新建板级配置；电机架空验证使能、零输出、正反向，再测试独立编码器和RB读数。

### F02 · P0：原路线终止条件不等于文杰杯完赛

`state_control.c:419—425`按路口序号达到`route_get_stop_fork_num()`停车；`route_config.h:12—15`阈值为54/22/39/38，源自原预赛/决赛。`route_config.c:195`附近仅为subject2/3选择路线表；`:409`停车阈值函数对非subject2采用决赛分支。故不能把菜单subject1/2/3直接当本校三科，更不能把阈值停车视为返回起点。

**处理：**独立建立本校三科ID、路线事件、起点离开/返回状态和任务记录；先实现经过两个有效元件的闭合路线。完整元件语义识别与全局覆盖是可选的后续增强，最低完赛仍需由场地判定实际N和返回。

### F03 · P0：主循环有约13秒固定停车

`user/cpu0_main.c:64—74`将`system_getval()`除以100000000后，达到13即`car_stop(STOP_REASON_TIMEOUT)`。SDK `zf_driver_timer.c:58`按10ns单位返回，因此静态可确定约13秒阈值；这不是PPT给出的赛事时限。若某科运行超过此时间，将在完成前停车。并非断言任何路线都不可能13秒内完成，而是其无规则依据且阻断更长路线。

**处理：**改为任务计时与独立、可配置的保护超时；数值依据场地与赛事执行要求确定。不能直接改成278秒。统一计时与回卷处理，启动时刻应与真正发车一致。

### F04 · P1：帧与偏差交接没有完整有效期协议

`user/cpu1_main.c:13—22`依赖完成标志处理图像并清零；CPU0控制读取共享偏差。`line.c:209`附近计算时先清零再更新偏差，读方可能拿到中间状态；只声明`volatile`不保证一组观察值一致。控制链中未见以帧序号/时戳为输入的完整图像过期停车机制，若视觉停更而丢线状态未更新，旧偏差可能继续被使用。

**处理：**明确采集/快照所有权；完整结果一次发布，包含seq、capture_ms、valid；控制检查年龄。通过暂停视觉、停止帧输入和高负载注入验证停机期限。该项是接口与静态风险，尚无实车复现记录。

### F05 · P1：路线保护模块与实际调用存在差距

CPU1运行环中`route_progress_begin_frame()`被注释（`cpu1_main.c:14`），但菜单预览存在调用；路线进度功能启用时需要核对每帧窗口更新。`ROUTE_ACTUAL_FORK_*`四个常量均为0，相关实际路口角度参考保护未启用。这里的0不是上游停车路口数，也不代表所有路线表为空。

**处理：**确定本车是否采用这套保护；采用则补齐调用、配置和去抖回归，不采用则在新任务层明确替代，不能仅因模块文件存在就勾选完成。

### F06 · P1：启动与停车路径需要重组

`initialize.c:68`先设置`start_flag=1`，`:103`才初始化INS，双核运行时可能提前处理业务；`motor.c:664`的`car_stop()`先关电机/控制中断，随后`:677`阻塞500ms，此函数也可从控制/保护调用链进入。这里风险是阻塞执行路径，不是电机会再运行500ms。

**处理：**全部状态就绪后一次发布READY；故障快速关闭输出并锁存原因，屏幕/保存/其他负载处理放到主循环。先验证单CPU，再考虑双核协作。

### F07 · P1：编码器量纲与控制频率未经本车标定

`encoder.c`注释为5ms，而实际控制定时器2ms；速度为counts/采样周期，不能直接解释为m/s。源实现有计数跳变限制与滤波，实际有效计数受A+DIR/AB模式、边沿和传动比影响，不能直接使用“1024线=车轮每转1024count”。负数取整、回卷、左右符号也需覆盖测试。

**处理：**实测车轮转一圈count、正反向和不同速度；统一物理单位或明确内部单位；按新采样周期重新设计PID与限幅，使用130电机重新调参。

### F08 · P1：内存预算与执行时间尚未通过证据验收

上游3072点轨迹数组约24KB；若在本项目84064B基础算法预算外保留该数组，将达到108640B，超过96KB算法桶。该计算是目标设计叠加估算，不是实际链接占用。屏幕完整帧64800B也不应默认引入。原500Hz控制、随帧视觉、频繁显示的负载与目标单CPU方案不同，不能套用“200MHz双核”推定实时性。

**处理：**首版关闭大轨迹缓存与完整屏幕缓存，提交.map逐区检查、栈/CSA水位、最长视觉耗时、IRQ耗时和控制抖动。总SRAM仍按240KB，不扩大规格。

P2项目包括超过适用门槛后的覆盖收益优化、精细元件分类、双核提速和复杂轨迹重定位。国赛75%门槛本身属于有效性要求，不归为P2；全国自制电路资格也必须在对应参赛阶段独立通过。先完成底层P0及P1，再低速跑圈与逐步提高覆盖。

## 5. 从当前基线到完赛的验收顺序

以下为项目建议门槛，不是赛事额外规则。每个阶段保留失败样例与停车原因，未通过不靠调高速度绕过。

| 阶段 | 工作与交付 | 通过条件 |
| --- | --- | --- |
| G0 规则与接线冻结 | 归档无调整确认、赛道/起终点说明、传感器及路线许可、引脚表 | 三科ID、允许输入、计分口径一致；所有电机/传感器资源无冲突 |
| G1 本车可构建 | 官方库适配工程、RB/相机/屏幕、非阻塞停车、固定版本配置 | ADS成功构建；.map按分区与预算通过；不上电机也能完成自检/报错 |
| G2 底盘可控 | 架空及低速验证PWM/DIR、左右轮速、IMU坐标和控制周期 | 正反向/停机正确；校准有效count；断开关键输入后按约定停车 |
| G3 视觉可回放 | 本车原始帧，白线/弯道/元件/T口/反馈回路/强弱光样本；共用C核心 | 无越界；每帧结果可解释；帧交接无撕裂；目标耗时和过期保护通过 |
| G4 科目1闭合 | 串联最小路线、离开起点/返回判断、至少两元件的裁判等效验证 | 建议20次完整记录中至少19次有效，且故障均安全停机；这不是官方门槛 |
| G5 科目2与3 | 分别适配T口、有源器件分支、反馈回路和返回路线 | 各科按G4同口径重复验证；路线推进无重复/漏计，实际N≥2且真实返回 |
| G6 赛前冻结 | 固件、参数、赛道版本、称重与计时记录、恢复流程 | 三科连续演练；保留视频/裁判计数、T1/T2/M/N和首次停车原因；可恢复已验证版本 |

最短实施顺序是：**本车驱动和可构建工程 → 可靠停止/帧交接 → 低速白线闭环 → 科目1有效返回 → 科目2/3路线执行 → 覆盖率和速度优化**。不能把当前资料基线直接跳称为已完成第一个固件阶段。

上述G4/G5的N≥2条件为校赛PPT基线；补充国赛口径验收时，应替换为对应75%覆盖目标，并加入起点中途误通过、达到覆盖但碰撞路肩、指定发车方向/任务变化等负例。20次19次通过为项目可靠性目标，不能降低赛事覆盖门槛。
